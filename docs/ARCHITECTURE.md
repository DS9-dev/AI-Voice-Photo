# AI Voice Photo — архитектура (этап 1)

## Происхождение

Проект выделен из VaMVoiceCompanion (копия рабочего дерева на 2026-11-15,
включая незакоммиченные правки оригинала). Дальше проекты развиваются
независимо: общего кода, общих настроек и общей истории git нет.

## Три изолированные части

1. **Electron-оболочка** (`app/`): окно и IPC. В `app/electron/main.js` —
   жизненный цикл и системный диалог выбора фото; `appController.js` —
   таблица каналов IPC без импорта Electron (тестируется без окна).
2. **Ядро** (`core/`, чистый Node.js): машина состояний, история сессии,
   доступ к LLM, метрики, конфигурация, профили персонажа, движок аватара.
   С моделями говорит только через интерфейсы (`core/providers/interfaces.js`).
3. **Голосовой сервис** (`services/voice_service/`, Python): отдельный
   процесс; микрофон, Silero VAD, faster-whisper, Silero TTS, вывод звука.
   Протокол — JSON-строки по stdin/stdout плюс бинарные кадры для
   возвращаемого звука TTS.

LM Studio — внешний сервер (OpenAI-совместимый API), приложение его не
запускает и не меняет. Привязки к конкретной LLM нет: `LLMProvider` —
интерфейс, `lmStudioProvider` — одна из реализаций; модель выбирается
автоматически или вручную.

## Что изменилось относительно VaMVoiceCompanion

Удалено (специфично для Virt-A-Mate):

- `core/vam/*` — TCP-мост к плагину VaM, протокол, привязки клипов Timeline;
- `vam_plugin/` (C#-плагин VVCBridge), `integrations/vam/`;
- `core/commands/*`, `core/actions/*` — прямые голосовые команды телу
  персонажа («сядь», «встань», «помаши рукой», скорость анимации),
  mock-исполнитель и исполнитель через VaM, редактор команд
  (`app/renderer/commandEditor.js`), страницы «Команды» и «VaM»;
- словарь команд в языковом пакете, режим ходов `command`;
- генераторы отчётов вех VC-M0…VC-M1.2 и бенчмарк роутера команд.

Сохранено без изменений: голосовой сервис, VAD/STT/TTS, LM Studio-провайдер,
оркестратор диалога (кроме удалённой ветки команд), профили персонажа и
голоса, защищённое ядро системного промпта, подсказки на ход, метрики,
диагностика, smoke-скрипты, оценки LLM, тесты.

Обобщено: вывод речи «через персонажа VaM» стал выводом «через движок
аватара» (`tts.output`: `local` | `avatar`). Логика, принятая на реальном
железе в VaMVoiceCompanion, сохранена: выбор вывода один раз на ответ,
откат на локальный вывод, микрофон закрыт до реального конца речи, Stop,
потеря связи с движком.

## Точка подключения анимации фото

`core/avatar/avatarEngine.js` описывает контракт `AvatarEngine`
(EventEmitter):

| Метод / событие | Назначение |
|---|---|
| `start()` / `stop()` | загрузка моделей, запуск окна/процесса рендера |
| `info()` | `{engine, state, detail, …}` для UI и диагностики |
| `setPhoto(path)` | новое исходное фото |
| `setConversationState({state, hearing, transcribing})` | для мимики слушания/размышления/ожидания между ответами |
| `speechBlocker()` | `null`, если речь можно отдавать движку, иначе причина |
| `setSpeechMode(on)` | речь идёт через движок (липсинк) или нет |
| `playSpeech({turnId, seq, sampleRate, audioMs, wav})` | один синтезированный фрагмент (16-bit PCM WAV); движок сам проигрывает звук синхронно с губами |
| `stopSpeech(turnId, reason)` | остановить и сбросить ответ |
| `speechStarted` / `speechEnded` | фрагмент зазвучал / закончился (`completed`, `stopped`, `failed`, …) |
| `connected` / `disconnected` | для движка в отдельном процессе |

Сейчас есть только `NullAvatarEngine` (`avatar.engine: "none"`): фото
показывается как есть, речь не принимается, ответы звучат локально — то
есть голосовой диалог работает ровно как в исходном проекте.

Чтобы подключить реальный движок: реализовать контракт (например, клиент к
отдельному Python-процессу рендера), зарегистрировать его в
`createAvatarEngine()`, добавить в `ENGINES`, а UI — вывести кадры движка в
`#photoStage` вместо статичного `<img>`. Ядро и оркестратор менять не нужно.

Поток данных при `tts.output = "avatar"`:

```
LLM (поток) → разбиение на предложения → голосовой сервис synthesize()
  → WAV-фрагменты → SpeechOutput → AvatarEngine.playSpeech()
  ← speechStarted / speechEnded ← движок (звук + губы)
  → оркестратор: SPEAKING → LISTENING только после реального конца речи
```

## Конфигурация

Новая секция `avatar`: `engine` (`none`), `photo` (абсолютный путь к фото;
JPG/PNG/WEBP/BMP до 25 МБ). Фото читает ядро и отдаёт интерфейсу как
data URL; интерфейс сам путей не выбирает — только через системный диалог.

## Независимость от VaMVoiceCompanion

- своё имя пакета (`ai-voice-photo`) → свой каталог данных Electron и своя
  блокировка единственного экземпляра: оба приложения могут работать
  одновременно;
- голосовой сервис запускается с меткой `--app=ai-voice-photo`, и
  `stop_helpers` / `doctor` трогают только свои процессы;
- свои `.venv`, `models/`, `node_modules/`, `config/user.json`.

Документы VaMVoiceCompanion о вехах VC-M0…VC-M1.2 лежат в `docs/legacy/`
как история принятых решений (в т.ч. о поведении персонажа и задержках).

## AVP-04: Ditto в приложении

```
SpeechOutput (core) ──play WAV──► avatar_service (Python, .venv_avatar)
                    ◄─speech_started/ended, level──┘   │
                                                       ├─ Ditto, непрерывный поток: тишина между ответами,
                                                       │  речь — на той же шкале времени (без перезапусков)
                                                       ├─ вывод звука (sounddevice): часы = DAC-время устройства
                                                       ├─ кадр k показывается, когда звучит его звук (k·40 мс)
                                                       └─ MJPEG http://127.0.0.1:<port>/stream.mjpg ──► <img> в окне
```

- Процесс и протокол — те же, что у голосового сервиса (`VoiceServiceClient`
  с компонентом `avatar`); команды: `init`, `set_photo`, `play`, `stop`,
  `configure`, `get_stats`, `record`.
- Код Ditto встроен в `services/avatar_service/ditto` (Apache-2.0, без
  изменений, кроме двух описанных в его README); ускорение для RTX 50
  (TensorRT 10, fp16) и гейт губ — `accel.py`; бесконечный поток — `live.py`.
- Stdin сервиса читается без висящего чтения (`PeekNamedPipe`): иначе
  загрузка DLL в потоке моделей блокируется на Windows.
- Интерфейс: живой поток поверх статичного фото; фон — размытое фото и
  мягкая палитра; свечение меняет только opacity/transform одного слоя по
  громкости звучащей речи (`avatarLevel`). Полноэкранный режим — класс CSS и
  `BrowserWindow.setFullScreen`, поток при этом не перезапускается.
