## 2. Совместимость с RTX 5060 Ti и что пришлось сделать

Среда изолирована: `T:\AI\AI Voice Photo\experiments\` (исключена из git), два отдельных venv (Python 3.10.11, PyTorch 2.7.1+cu128). Приложение, его `.venv`, системный CUDA, драйвер и глобальные компоненты не менялись. WSL2 не понадобился. Подробности сборки — `experiments\README.md`, точные версии — `env_*.lock.txt`.

### Ditto

| Проблема | Решение | Статус |
|---|---|---|
| Готовые TensorRT-движки собраны под TensorRT 8.6 (Ampere), TensorRT 8 не поддерживает Blackwell | Путь PyTorch-весов (выпущены в 2025-07) + ONNX Runtime 1.23 (CUDA) | работает |
| Блендинг собирается Cython на лету (нужен компилятор) | Запасная реализация на NumPy (идентичная формула). Фактически Cython собрался через MSVC Build Tools | работает |
| PyTorch-путь медленный: 5,5–8 кадр/с; генерация движения (LMDM) — 792 мс на 400 мс аудио | **Ускоренная сборка** `scripts/ditto_accel.py`: LMDM и декодер → ONNX → **TensorRT 10.13** (в venv, движки собраны на этой карте); деформация — PyTorch fp16 с исходными признаками на GPU; вклейка лица — только в области лица с кэшированной маской; вывод ограничен 1024 px | **27,7 кадр/с** |
| Сеть деформации использует 5-D GridSample: в ONNX Runtime его нет, TensorRT-плагин Ditto — только Linux `.so` | Оставлена в PyTorch fp16 (17 мс/кадр) | ограничение, не блокер |
| Потоковый режим выпущен только как TensorRT-конфиг | Собран PyTorch-конфиг с параметрами онлайн-режима (10 шагов, overlap 70) | работает |

Профиль одного кадра (рендер, свободная карта): деформация 17 мс, декодер (TRT fp16) 14 мс, вклейка 30–43 мс (CPU, в отдельном потоке). Генерация движения — 104 мс на 400 мс аудио.

### SoulX-FlashHead Lite

| Проблема | Решение | Статус |
|---|---|---|
| `xfuser` (параллелизм на нескольких GPU) импортирует Unix-модуль `fcntl` | Заглушка `shims/xfuser` — на одной карте эти функции не вызываются | работает |
| `torch.compile` требует Triton | **eager-режим** (по умолчанию в замерах). Проверен и `triton-windows` 3.3.1: даёт +10% (722 против 798 мс на кусок), но прогрев 3,5 мин при первом запуске | работает в обоих вариантах |
| flash-attn / SageAttention на Windows | не нужны: в коде есть запасной стандартный SDPA PyTorch | работает |
| Вертикальные фото: центральная обрезка срезает верх головы | Режим `face_crop` (поиск лица) для ваших фото | работает |
| `nvidia-nccl`, `xformers`, `gradio` из requirements | не установлены (не нужны для одной карты и скриптов) | — |

## 3. Замеры (свободная карта, аудио подаётся в темпе реального времени)

Метод: аудио отдаётся движку кусками по мере «появления», как его будет отдавать живой TTS. Отставание — насколько кадр готов позже момента, когда он должен быть показан, если показ начинается одновременно с началом аудио. Полные таблицы по каждому прогону — `experiments\outputs\summary.md` (там же два дополнительных прогона с LLM: `withllm__*`, `llmturn__*`; в медианы ниже они не входят).

| Медиана по 11 прогонам | Ditto | FlashHead Lite |
|---|---|---|
| Пропускная способность | 27,7 кадр/с | 30,0 кадр/с |
| Первый кадр / первый кусок | 2,1 с | 2,5 с |
| Отставание: медиана / максимум | 1,2 с / 2,06 с | 1,77 с / 2,49 с |
| Рост отставания | −87 мс/с (догоняет) | −57 мс/с (догоняет) |
| Время куска 0,96 с: медиана / максимум | — | 800 / 1534 мс (максимум — первый кусок) |
| Макс. пауза между готовыми кадрами | 170 мс | кусками по 0,96 с |
| VRAM пик сверх базы | 4,33 ГБ | 6,10 ГБ |
| Загрузка GPU | 75% | 76% |
| Загрузка модели / подготовка фото | 8 с / 2,7 с | 5 с / 1,4 с |

**Что это значит для диалога.** Отставание не растёт, значит оба движка устойчиво держат реальное время. Цена — фиксированная стартовая задержка: если звук играет движок аватара синхронно с губами (так задумано в контракте `AvatarEngine`), ответ начнёт звучать на **~2 с (Ditto)** или **~2,5 с (FlashHead)** позже, чем сейчас. Это добавка к текущей задержке «конец вашей фразы → первый звук».

### Совместная работа с LLM (LM Studio, Qwen 3.5 9B Q4_K_M, та же модель, что в приложении)

| Сценарий | LLM, ток/с | Ditto | FlashHead Lite |

| LLM одна | 68,2 | — | — |
| Один ответ LLM (300 токенов) в начале речи — как в реальном диалоге | 66,7 / 62,6 | 26,6 кадр/с, отставание без изменений | 30 кадр/с, отставание без изменений |

| Клип | Ditto | FlashHead Lite |

## 4. Наблюдения по качеству (мои, предварительные)

- **Сохранение внешности.**
  - Ditto: лицо на всех кадрах совпадает с фото (веснушки, форма глаз и губ, волосы), фон и одежда не меняются — это пиксели исходника.
  - FlashHead перерисовывает весь кадр 512×512. На `owner_a` (студийный) заметно меняет пропорции: лицо шире, веки тяжелее, взгляд «сонный». На `owner_b` и `example` сходство лучше.
- **Губы и русская артикуляция.**
  - Ditto открывает рот и показывает зубы, следует слогам во всех клипах.
  - FlashHead на `owner_a` в артикуляционном клипе почти не открывает рот, на `owner_b` — нормально. Похоже, исходное выражение лица (закрытый рот) сильно влияет на FlashHead.
- **Мимика и голова.** FlashHead даёт более свободные движения головы и плеч (генерирует их сам). Ditto сдержаннее: небольшие повороты и наклоны, моргание, брови.
- **Артефакты.**
  - Ditto: граница вклейки не видна. На широком открытии рта зубы и внутренность рта мягче остального лица (декодер 512 px).
  - FlashHead: разрешение 512×512, на крупном плане мягче. Цвет и свет стабильны, дрейфа за 48 с не видно.
- **Длинный клип 48 с:** ни один движок не «поплыл» к концу.

Это наблюдения по отдельным кадрам. Вы оцениваете видео целиком — ваше мнение имеет приоритет.

## 6. Блокеры и риски

- **Блокеров запуска нет.** Оба движка работают нативно на Windows и Blackwell.
- **Конкуренция за GPU:**
  - если LLM генерирует долго (длинные ответы, «размышления» модели) или на карте работают игры и браузер с видео, анимация не держит реальное время;
  - для интеграции понадобится буфер или приоритет и, возможно, ограничение длины ответа LLM;
  - у FlashHead запас VRAM всего ~1,4 ГБ.
- **Стартовая задержка ~2 с** добавляется к ответу. Это главный компромисс «живого» лица.
- **Ditto:** зависимость от моих обходов (TensorRT 10 вместо 8, PyTorch-деформация); исходный проект с Windows и RTX 50 не тестировался авторами.
- **FlashHead:** только 512×512 и перерисовка всего кадра; заметное влияние исходного выражения лица на артикуляцию; нет управления мимикой.
- **Лицензии:** обе Apache-2.0. Детектор лица Ditto — InsightFace (только некоммерческое использование), FlashHead использует mediapipe.

## 7. Предлагаемые следующие шаги (после вашей визуальной приёмки, отдельным заданием)

1. Выбор движка по вашему просмотру.
2. Для выбранного движка — короткий прототип непрерывной работы вне приложения: покой → речь → покой без перезапуска, с морганием и микродвижениями в паузах.
3. Уменьшение стартовой задержки и правила разделения GPU с LLM.
4. Только после этого — интеграция за контрактом `AvatarEngine` (отдельный процесс, кадры в `#photoStage`, звук играет движок).
